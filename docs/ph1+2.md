## Agent 1: Daily Entry Agent (5 tools)

**Files:** `specs/agent-daily-entry.md`, `backend/tools/{cash_tools,transaction_tools,receipt_tools,bank_tools,petty_cash_tools}.py`

| Tool | Approval | How It Works | Input | Output | DB Tables |
|---|---|---|---|---|---|
| `check_cash_position` | ❌ No | Queries `journal_entries` up to as_of_date, aggregates cash accounts (1000+ prefix). Deterministic sum — no AI. | `as_of_date: date`, `account_id: str\|null` | `account_id`, `closing_balance`, `total_debits`, `total_credits`, `warning` | `journal_entries` (read) |
| `record_transaction_nl` | ❌ No | Parses plain-English description → regex extracts amount → keyword-maps to expense account → creates balanced debit/credit journal entry. Duplicate detection via amount+date+description fuzzy match. | `description: str`, `posted_date: date`, `reference: str\|null` | `entry_id`, `debit_account`, `debit_amount`, `credit_account`, `credit_amount`, `status` | `journal_entries` (write) |
| `process_receipt_image` | ✅ Yes | Simulates LLM vision extraction (vendor, amount, date from image data prefix). Validates format/size first. Confidence determines status. Saves with `pending_approval` status. | `image_data: str` (base64), `image_filename: str`, `suggested_account: str\|null` | `extraction_id`, `vendor_name`, `total_amount`, `confidence`, `needs_approval: true`, `status` | `receipt_extractions` (write) |
| `check_bank_transactions` | ❌ No | Filtered query on `bank_transactions` by date range, account, status. Returns paginated list with aggregate totals. | `account_id`, `from_date`, `to_date`, `status`, `limit` | `transactions[]`, `total_count`, `total_debits`, `total_credits`, `truncated` | `bank_transactions`, `bank_accounts` (read) |
| `manage_petty_cash` | ❌ No | 3 actions: `expense` (deduct from fund balance), `add_fund` (add to balance), `check_replenishment` (compare vs threshold). Alerts when balance below threshold or negative. | `action`, `fund_id`, `amount`, `description`, `paid_by` | `fund_id`, `current_balance`, `needs_replenishment`, `message`, `transactions[]` | `petty_cash_funds`, `petty_cash_transactions` (read/write) |

**Edge cases tested:** 28/28 passing
- cash position: no transactions, account not found, negative balance, multi-account consolidated
- transaction nl: no amount, duplicate detection, misc category fallback
- receipt: non-receipt image, blurry, zero/negative amount, wrong format
- bank: no transactions, account not found, date range error, limit truncated
- petty cash: expense exceeds balance, fund not found, zero add amount

## Agent 2: Ledger & Master Data Agent (8 tools)

**Files:** `specs/agent-ledger-master-data.md`, `backend/tools/{ledger_tools,asset_tools,contact_tools}.py`

| Tool | Approval | How It Works | Input | Output | DB Tables |
|---|---|---|---|---|---|
| `create_journal_entry` | ❌ No | Takes exact debit/credit accounts + amounts. Validates balance (debits = credits). Generates auto-incrementing JE ID. | `description`, `posted_date`, `debit_account`, `debit_amount`, `credit_account`, `credit_amount` | `entry_id`, `debit_account`, `debit_amount`, `credit_account`, `credit_amount`, `status` | `journal_entries` (write) |
| `get_general_ledger` | ❌ No | Queries all `journal_entries` in date range, groups by account, calculates net movement per account. Optional account code prefix filter. | `from_date`, `to_date`, `account_code_prefix` | `accounts[]` (account, total_debits, total_credits, net_movement), totals | `journal_entries` (read) |
| `suggest_chart_of_accounts` | ✅ Yes | Maps business type → standard chart structure (8 business types: retail, freelance, manufacturing, tech_startup, restaurant, non_profit, real_estate, service_based). Returns suggestion — nothing saved until approved. | `business_type: str`, `description: str\|null` | `accounts[]` (account_code, account_name, account_type, description), `needs_approval: true` | None (in-memory only) |
| `get_ap_subledger` | ❌ No | Filters `journal_entries` where debit starts with "2000" (liabilities/AP). Groups by vendor reference. Shows total outstanding. | `from_date`, `to_date`, `vendor_contact_id` | `entries[]`, `total_outstanding` | `journal_entries` (read) |
| `get_ar_subledger` | ❌ No | Filters `journal_entries` where debit starts with "1200" (AR/receivables). Groups by customer reference. | `from_date`, `to_date`, `customer_contact_id` | `entries[]`, `total_outstanding` | `journal_entries` (read) |
| `get_payroll_ledger` | ❌ No | Queries `payroll_entries` table. Flags when deductions exceed salary. | `from_date`, `to_date`, `employee_name` | `entries[]` (employee, salary, deductions, net_pay), totals, warning | `payroll_entries` (read) |
| `categorize_fixed_asset` | ✅ Yes | Keyword-based category detection → suggests depreciation method, useful life, residual value. Saves with `pending_approval` status. | `asset_name`, `purchase_cost`, `purchase_date`, `asset_category` | `asset_id`, `suggested_useful_life`, `suggested_depreciation_method`, `suggested_residual_value`, `needs_approval: true` | `fixed_assets` (write after approval) |
| `manage_contact` | ❌ No | CRUD for vendors/customers. 4 actions: add, update, delete, search. Duplicate detection, partial-name search via ILIKE. | `action`, `contact_type`, `contact_name`, `phone`, `email`, `address`, `tax_id` | `contact_id`, `contact_name`, `contact_type`, `action_performed` | `contacts` (read/write) |

**Edge cases tested:** 46/46 passing
- create_journal_entry: debit≠credit error, duplicate ID, amount validation
- get_general_ledger: empty date range, date order error, prefix filter
- suggest_chart: 8 business types, alias resolution, unknown type
- AP/AR: with entries, empty, vendor/customer filter
- payroll: with entries, employee filter, deduction warning, empty
- categorize_fixed_asset: 6 asset categories, cost<residual error
- manage_contact: add, update, delete, search, duplicate detection, not-found error

## Architecture Summary

### Tech Stack
| Layer | Technology |
|---|---|
| Model | Groq `qwen/qwen3.6-27b` (primary) → `llama-3.1-8b-instant` (fallback) → Cerebras `gemma-4-31b` (last resort) |
| Agent Framework | OpenAI Agents SDK (Chat Completions API) |
| Backend | Python 3.12, FastAPI |
| Database | PostgreSQL 16 (`postgresql://postgres:postgres@localhost:5432/ai_accountant`) |
| Data Validation | Pydantic v2 (every tool input & output) |
| ORM | SQLAlchemy 2.0 |
| External APIs | Groq (openai/v1), Cerebras (.ai/v1) |

### Orchestrator Flow
```
User Request → Orchestrator Agent → Selects Right Tool → Calls Function
    → Pydantic Input Validation → SQLAlchemy Query → Pydantic Output → Natural Language Response
```
